# Note feature ideas

These sketches capture situations worth exploring. When revisiting one, start with how people read, write, or find their notes. The examples are open to revision or dismissal.

## Reading mode

Someone opens a note on their phone to read or copy a passage and a tap brings up the keyboard. Would a reading mode help? Could a change to how the editor takes focus solve that annoyance with one fewer mode to manage? Consider how someone moves from reading a passage to editing that same passage.

## Mentions and linked notes

A writer wants to refer to a project brief from meeting notes. Typing `@` to find another note by title is one possible entry point. How often does the writer need a quick peek, sustained side-by-side reading, or a jump to the other note?

Explore viewing the reference alongside the source on a wide screen in both the note modal and full-page document view. A useful comparison is following the link and returning to the same sentence. Which feels better for a one-line lookup? What about consulting the brief throughout a writing session? The answer could change with the available width or how often the writer moves between notes.

## Tags and filtering

Someone wants to revisit a group of notes they think of as “research,” even when the notes use different words. Would assigning tags save enough time to justify maintaining them? A single tag filter, combinations of tags, or a saved search could each suit different habits. If tags apply to encrypted notes, consider what a tag name reveals and who should be able to see it.
