# Encryption candidate release evidence

Updated 2026-11-15. **Production/real-note beta verdict: NO-GO.** This is a local candidate, not a release approval. Both enrollment and creation remain disabled by default. No PR, merge or deployment is authorized. A finite passing test matrix cannot establish the absence of unknown defects or operational risk.

## Candidate and scope

The local remediation commit is `66bdd86969dc8040adc0bc108a130012dd778cdf`, based on audit revision `3e2333c0b0a2f39fc63d2d4a9bd43c66cd37fc10`. The release follow-up adds authentication-expiry recovery, repeated-unlock protection, canonical codec/storage performance fixes and the executable checks below. The pre-encryption comparison is `609afe5a9c24af2d0850e0b35c7c9a0e05fc5c1e`.

[The source manifest](note-encryption-release-source.json) identifies the exact source bytes, reference revision and production build. It includes the independently authored backup runner. Review the local commit containing that manifest and its diff; do not infer candidate identity from the branch name alone. Logs and synthetic browser artifacts are retained locally under `.playwright-mcp/` and are ignored by Git.

The application changes are limited to these safety/performance issues:

- HTTP 401 is an authentication pause, distinct from a transport retry or permanent refusal. The checkpoint retains the exact flight and later edits. Automatic, reconnect and reopen sends remain stopped. An explicit resume checks the session belongs to the original owner before sending; another owner's session sends no flight. EN/VI guidance links to sign-in and exposes Check sign-in and resume.
- Repeating Unlock while already active cannot replace the root or advance the editor's epoch. The control is disabled while unlocked, and runtime activation is idempotent for the active owner/vault. Real locking, stale epochs and other-owner/vault fences remain effective.
- A confirmed pre-existing startup autofocus race is also repaired: a delayed title-focus callback could steal focus after a user chose the body and redirect subsequent keys into the title. The same deliberate click/key regression failed on the pre-encryption baseline. Initial focus now checks ownership and applies selection/focus in one callback, preserving the default title-end focus when the user has chosen no field.
- Early search input could be erased during React's native view-transition preparation, when delegated input events are paused. A scoped native `beforeinput`/`compositionstart` listener finishes that pending commit before the browser changes the controlled value. Original focus timing and normal list animations remain. The held-commit regression also fails on the pre-encryption baseline. Separate immediate typing, bulk insertion, second-character and simulated-composition checks cover the repair; physical IME usability remains a device gate. The stale-card test now requires an actual settled search result before exercising acknowledgement reconciliation.
- Canonical base64url validation checks alphabet, length and unused final bits without repeatedly decoding large fields. Native typed-array codecs have compatible fallbacks. A recovery checkpoint validates/serializes once and seals those exact bytes. Stored-envelope byte counts use the exact ASCII field lengths and JSON overhead, checked against the previous byte-count calculation. No KDF, authenticated-data, ciphertext, size or commit-fence rule was weakened. No timing workaround remains.

The ordinary browser default blocks service workers, but its narrow worker-navigation case explicitly enables them. The new encryption release cases explicitly allow and verify the active production worker. A default configuration alone is not evidence that a given case did or did not exercise a worker.

The feature adds one direct runtime dependency. Both the lockfile and installed package resolve `@simplewebauthn/server` to `14.1.0`. On 2026-11-15 this version fell outside the affected ranges of the three advisories listed by its maintainer. This check covers that package and those three advisories. [Certificate fetching](https://github.com/MasterKale/SimpleWebAuthn/security/advisories/GHSA-j3h4-m3m2-7p7j), [revocation cache](https://github.com/MasterKale/SimpleWebAuthn/security/advisories/GHSA-2g3p-m8c9-hhwh), [attestation trust chain](https://github.com/MasterKale/SimpleWebAuthn/security/advisories/GHSA-6hxq-p678-4hr2).

An isolated Windows install with pnpm 11.22.0 materialized all 693 packages from the local cache using the frozen lockfile, with lifecycle scripts disabled and zero downloads. The vault directly imports its WebAuthn implementation. NextAuth advertises an optional `@simplewebauthn/server` peer of `^9.0.2`, outside the vault's locked `14.1.0`. The configured account sign-in providers are Google and a development-only Credentials provider. Enabling NextAuth's own WebAuthn login provider would require resolving and testing its separate peer requirement.

## Desktop performance evidence

Machine: Windows 11 build `10.0.26200`, Intel Core i5-12400, 12 logical CPUs, 32 GiB RAM; Playwright 1.65.0 Chromium `158.0.8127.18`. Thirty warm sequential samples per operation, plus separately reported first-operation samples after setup. These are neither process-cold nor mobile measurements. Native codecs were available. Only synthetic fixtures were used; no content telemetry is added to the application.

[The benchmark](../scripts/note-encryption-benchmark.mjs) separately measures note sealing, selected detail opening/validation/sanitization, conflict sealing/commit, paginated header scanning, visible-page title decryption and the unchanged 600,000-iteration PBKDF2 profile. Long-task measurements are scoped to each operation. Fixture construction/large bulk insertion is reported separately and is not presented as typing performance.

The final measurements are retained in `.playwright-mcp/release-benchmark.json`. Before the final serialization reuse, maximum JSON-expanded seal/commit had p95 505.1 ms and 30/30 long tasks up to 482 ms. A timer yield alone did not meet the largest-record requirement; it was removed. After codec/serialization changes, the measured operation phases have no observed tasks above 50 ms, including the largest schema-bounded recovery record. Decoded/stored worst-shape sizes measured 6,132,141 / 8,176,304 bytes, within the existing 8 / 12 MiB limits. Twenty separately sealed retained records of that shape are used behind 1,000 headers. Header scans read zero payloads, perform zero PBKDF2 calls and make zero detail requests. Fifty visible title-only decryptions were separately measured over 30 runs without body reads or KDFs.

The maintainer also measured the forced fallback with both native typed-array codecs disabled. The previous fallback produced worst-recovery p95 374.6 ms and 30 long tasks up to 357 ms. Direct ASCII encoding with the same canonical bytes reduced that to p95 61.5 ms, with zero phase long tasks; maximum JSON p95 was 48.1 ms and normal-record p95 2.6 ms. Evidence: `.playwright-mcp/release-benchmark-fallback.json`, with the earlier result in `.playwright-mcp/typing-attribution/fallback-before.json`. The runner supports `--fallback`. This is fallback behavior on desktop Chromium, not evidence for a different engine or physical phone.

The real-editor test separately measures 30 valid approximately 32 KiB UTF-8 whole-body replacements through input, editor rendering and durable IndexedDB commit, after mounting/setup. These `fill` operations resemble bulk input and are not single-key typing. It also measures the ordinary editor with the same fixture. The pre-optimization encrypted run observed a 79 ms task; the first post-optimization full run observed one 80 ms task. Both observations are retained. A separate renderer trace reproduced a 50.6 ms first-replacement task in text-input/layout before the debounced encryption/checkpoint; it does not retrospectively attribute the earlier untraced events. No further long tasks occurred in 29 later encrypted replacements or 30 ordinary replacements. A separate 30-single-key test on an already committed 32 KiB note reported encrypted p50/p95 526.6/533.1 ms and ordinary 535.4/539.5 ms, with zero long tasks in either run. Evidence: `.playwright-mcp/typing-attribution/{result,incremental}.json`. On final build `CF33JZKWO4ocg_hSxnWXw`, whole-body replacement p50/p95 was 541.6/562.1 ms encrypted versus 552.4/560.9 ms ordinary, with one 52 ms task in the encrypted run and none ordinary (`release-typing.json`). A successful desktop measurement does not waive phone timing, browser profiling, queue/crash, quota or accessibility gates; whole-body input/layout still has observed tasks over 50 ms.

A limited simple-text workaround passed on build `bw-bRaxyH1Db-VhjlbFQS`: after reload/unlock, read the refused browser version, close it, explicitly create a new encrypted note and re-enter the title/body; the server acknowledged a different ID with exact decrypted text, and the refused destination was not resent. The cold-offline shell is not supported for protected routes. Loaded-shell offline work is the tested contract; installed-PWA/OS termination/background/storage-eviction behavior remains a physical-device check. Same-origin malicious code, a compromised unlocked device or clipboard exposure remain outside the confidentiality promise of browser E2EE. Losing all credentials and recovery material still loses access; server backup cannot recover a never-uploaded browser edit.

Deploy additive migrations and server protections before any future client rollout. Keep both flags false until the applicable gates pass. Disabling flags must preserve existing encrypted unlock/read/save/recovery/deletion. Once ciphertext or newer strict recovery records exist, roll forward: do not roll back to a plaintext-only server or an older strict-schema client, and do not decrypt/mutate stored data automatically. Conversion directions, attachments/sharing, persistent device unlock, portable encrypted export and client-wide encrypted search remain outside the candidate's first-beta scope; conversion gates apply before conversion is implemented or enabled.

## Final closeout

The final local build is `CF33JZKWO4ocg_hSxnWXw`. All **115 production-browser cases passed in one clean run** (8.5 minutes), alongside 18/18 repeated focused search cases, 21 encryption unit checks, four server checks, TypeScript/ESLint and the production/Serwist build. Evidence: `.playwright-mcp/release-final-matrix.log`, `release-search-final.log`, `release-final-encryption-elevated.log`, `release-final-server.log`, `release-final-lint.log` and `release-final-build.log`. Independent PostgreSQL archive recovery passed in fresh Chromium, Firefox and desktop Windows WebKit profiles on this exact build.

The source manifest covers 87 changed source/test/configuration files against the baseline. A post-suite exact-byte recheck found zero mismatches; digest `db652e2f6eaf5bec8b73b17c63f1d9d9c7f502109a8ad87d449c024cb2c1b7ca`. Prior full-run failures (106/107 and 109/110), input-loss traces and failed repair probes remain retained. They are not replaced by the final success or attributed to fixtures alone.

The required targeted UI review **passed**: Paper & Ink light, EN 1440×1000 and VI 390×844; paused-sync guidance/actions, disabled active Unlock, ordinary title/body/caret focus, mobile read/edit and immediate search/Clear/Escape. No HIGH/MED findings. Status contrast was 7.21:1 and actions at least 13.20:1, with visible keyboard focus and no horizontal overflow. The development sampler captured no native list-animation effects; this visual check remains unverified, while the final production motion regression passed. This review is not the independent security or usability/screen-reader study.

Automatic approval rejected transferring the signed fixture cookie/JWT to browser automation. The reviewer did not retry that transfer: documented same-origin `qa@test.dev` Credentials sign-in, normal synthetic vault setup and a context-local PUT-401 mock safely reached the paused state. The mock was removed and browser cleanup succeeded. All task preview servers were stopped; the exact remediation and baseline databases, their environment files, signed review fixture and expanded baseline checkout were removed. The baseline zip, logs and original failure traces remain. The shared development database and other workspace artifacts were preserved. Repository flags remain false; local flags are unset (disabled).

The real-user release decision remains **NO-GO** until the independent security, physical-device/provider, mobile performance, EN/VI usability/accessibility, production/operator and complete permanent-refusal recovery gates above are satisfied. No remote push, PR, merge, deployment or enrollment enablement is authorized by this local closeout.
